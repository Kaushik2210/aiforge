1. Do the cheap "no" answers first. A negative `attempt` raises `ValueError` before anything else; then return `None` for: a status that is not worth retrying (only 429, 500, 502, 503 and 504 are), `attempt >= max_retries`, or a method that is not safe to repeat. Build one set of the idempotent methods (GET, HEAD, PUT, DELETE, OPTIONS) and compare `method.upper()`.
2. POST and PATCH are not idempotent, but a request that carries an `Idempotency-Key` header is safe to repeat, because the server uses the key to spot a duplicate. Header names are case-insensitive, so build `{k.lower(): v for k, v in headers.items()}` once and look up lower-case names. Treat an empty value as no key.
3. For 429 and 503, read `retry-after`. If, after stripping spaces, it is only ASCII digits (`value.isascii() and value.isdigit()`), return `float(int(value))` (it is not capped: the server knows best). Anything else (a date, `1.5`, `-3`, `abc`) is ignored, so fall through to backoff. Backoff: `min(cap, base * 2 ** attempt)`. With the defaults, attempts 0 to 4 give 0.5, 1.0, 2.0, 4.0 and 8.0 seconds, and attempt 5 gives `None`. Return a float.
