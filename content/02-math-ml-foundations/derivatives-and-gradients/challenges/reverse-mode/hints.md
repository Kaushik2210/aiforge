Make each operation build a new `Var` that remembers its parents and the local derivative of the result with respect to each parent (for `a * b` the locals are `b.value` and `a.value`; for `a + b` they are 1 and 1; for `tanh(a)` it is `1 - tanh(a) ** 2`). Turn a plain number into a parentless `Var` so one code path handles constants. For `3 - x` and `1 / x`, lift the number and reuse the normal method, so the order stays right.
2. `backward` has three jobs in this order: collect every Var reachable from `out` in an order where each Var comes after all of its parents (an iterative depth-first search with an explicit stack and a `seen` set of `id`s; push a "finished" marker before pushing the parents, and add the node to the list when you pop that marker), reset all their grads to 0.0, then set `out.grad = 1.0`.
3. Walk the list in reverse, so every Var is handled before the Vars it was built from. For each Var, add `node.grad * local` into each parent's `.grad` with `+=`, never `=`: a Var used twice (`x * x + x`) receives one contribution per use and they must add up. Check by hand: for `y = x * x + x` at `x = 3`, `x.grad` is `2 * 3 + 1 = 7`.
