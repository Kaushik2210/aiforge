1. A `Dual(value, deriv)` is a pair. Every operation computes the new value the normal way and the new derivative with the matching rule: sum rule, product rule, quotient rule. Turn a plain number into `Dual(number, 0.0)` first so one code path handles both. For the reversed forms (`2 * d`, `1 - d`, `1 / d`) lift the number and reuse the normal method on it, because subtraction and division care about the order.
2. For `**`, the new value is `value ** n` and the new derivative is `n * value ** (n - 1) * deriv`. The `* deriv` at the end is the chain rule; forgetting it is the classic bug. Handle `n == 0` on its own (value 1.0, derivative 0.0) so `0 ** 0` never multiplies by a power of zero. For the functions, the chain rule always looks like "outer derivative at the value, times the inner derivative": `exp` gives `exp(v) * d`, `log` gives `d / v`, `sin` gives `cos(v) * d`, `cos` gives `-sin(v) * d`.
3. A function given a plain number must give back a plain float, and given a Dual must give back a Dual. `derivative` seeds the input with `Dual(x, 1.0)` (the derivative of x with respect to itself is 1), runs `f`, and reads `.deriv` of the result; if `f` returned a plain number, answer `0.0`. Check `log` for a non-positive value BEFORE computing, for both kinds of input.
